# RF-E2E (addendum 6): reader-faithfulness of a whole-volume character card, with the input channel and the memory channel separated

Written 2026-10-16 about 20:30 IST, **before any card is generated and before any analysis of cards**. The 68 confirmatory events (`PD_confirm_events_v1.json`, frozen, sha in `MANIFEST_PD_CONFIRM_v2.json`) and the 3,522 Gutenberg texts already exist; no new events are mined and no event, cut or audit label is changed. Owner instruction of the same day: build the strongest defensible novelty result with metrics within about three hours, for a journal manuscript. Label provenance: TEXT-DERIVED oracle (the book's own reveal sentence and cut), model-selected events, no human labels. Local models only (ollama, temperature 0, no cost); no OpenAI; nothing is pushed.

## Why this experiment
Channel 2 (derivation look-ahead) has so far been shown on one pipeline (EchoTales' deterministic persona stage). A reviewer can say it is a defect of that code. The commonest design in position-aware reading assistants is different: a language model writes a **character card** from passages that mention the character, the card is built once for the whole volume and stamped at the character's first mention. This experiment tests that second, generic design with the same truncate-and-rebuild oracle, and it separates the two leakage channels in one measurement.

## Design
- **Unit:** the event. **Reader position:** the pre-registered cut of the event (just before the reveal chapter), `PD.locate(ev, text)["cut"]`.
- **Builds (card for the aliased character, at most 80 words; prompt below):**
  - **W (whole-volume build):** evidence = up to 12 passages evenly spaced over **all** alias mentions in the whole book (`PD.spaced`); each passage is the text from 500 characters before to 700 characters after the mention. The card is built once and served at the cut (stamped at first mention).
  - **P (prefix build):** the same rule over alias mentions whose sentence ends at or before the cut, and every passage is clipped at the cut. This is the truncate-and-rebuild reference. A versioned build equals P at every position by construction (FORMAL P6), so it is not run separately.
- **Text arms:** **orig** (original names) and **ren** (the frozen consistent letter cipher `renamers_for(books)[gid][0]`, applied to the passages and to the alias).
- **Prompt (fixed):** "Write a character card of at most 80 words for the character referred to as {ALIAS}, using these passages from the book. Passages:\n{PASSAGES}\nCard:". No instruction about outside knowledge.
- **Models:** `qwen2.5:7b`, `llama3.1:8b`, `mistral:7b-instruct` via local ollama, temperature 0, seed 20261016, 8,192 context, 160 new tokens; each cell run once.
- **Leak, rule A (text-derived, primary):** let T be the capitalised tokens of at least 3 letters of the event's identity name that do **not** occur in `text[:cut]` (the reader's prefix), excluding honorific words. A card **leaks** if it contains a token of T as a whole word. In the ren arm T and the card are compared after the same cipher. An event is **rule-A measurable** if T is non-empty, the alias has at least one mention before the cut and at least one after the reveal sentence.
- **Leak, rule B (model-judged, secondary):** a fixed judge that is not one of the three generators (`qwen3:8b`, thinking off, temperature 0, JSON output) reads only the card, the alias and the identity name (both in the arm's naming) and answers whether the card states or clearly implies that the character called the alias is the same person as the identity. Applies to every event whose alias has mentions before the cut and after the reveal. Model-labelled; reported as such.
- **Amendment before any card existed (20:45 IST):** a dry count without model calls showed that rule A applies to only 19 of 68 events (in 38 the identity is a character already named in the prefix, so a name match cannot separate a disclosure from an ordinary mention); rule B was added for that reason, and the primary set changed from EXPLICIT-only to EXPLICIT plus IMPLIED because EXPLICIT-only leaves 11 events. Nothing else changed.
- **Primary set:** rule-A measurable events with audit EXPLICIT or IMPLIED (19 events, all splits, since nothing here was tuned on the dev split). **Secondary:** rule B on all measurable events with audit EXPLICIT or IMPLIED, and either rule on EXPLICIT only. Reported per model and pooled (mean over models of the per-event leak, event-cluster bootstrap, 10,000 resamples, seed 20261101). **Model order:** qwen2.5:7b, llama3.1:8b, mistral:7b-instruct; a model that does not finish by 22:45 IST is reported "not run".

## Hypotheses and decision rules (fixed now)
- **RF1 (input channel, primary; rule A on the primary set; repeated with rule B as secondary).** Leak(W, ren) minus Leak(P, ren), pooled over the models that finished, is at least +10 percentage points with a 95% lower limit above 0, and the sign is positive for at least 2 of 3 models. Supported only if all hold; otherwise not supported.
- **RF2 (validity check, not a hypothesis).** Leak(P, ren) must be 0 up to a few cases: the renamed identity token cannot be produced from memory or from the prefix. If it exceeds 5% of events, the leak rule is flagged invalid and RF1 is reported as not interpretable.
- **RF3 (memory channel, descriptive).** Leak(P, orig) minus Leak(P, ren): leakage with no input path, from the weights only. Reported with its interval and no threshold.
- **RF4 (both channels, descriptive).** Leak(W, orig) minus Leak(P, orig) and the decomposition into input only (W-ren), memory only (P-orig) and the union (W-orig).
- **Utility check (descriptive):** the share of cards that mention the alias surface or its cipher form, and the mean card length, per build, so that a leak difference is not produced by empty cards.

## Declared limits
Passages are sampled by mention, so the whole-volume build sees reveal-side passages only through the alias; a build that summarises the whole book would leak at least as much. Local 7 to 9B models are weaker than the models of a product; the claim is about the design, not about a specific assistant. The memory channel (RF3) is a lower bound because renaming removes only name-keyed memory. Events are model-selected and model-audited; no human check. If the run does not finish for a model, that model is reported "not run" with the reason and excluded from the pooled statistic; no cell is re-run to change a result.
