# PD CONFIRM v2, addendum 1: extra book rounds when the first 120 books cannot yield enough events (written before any event is mined)

Written 2026-10-16 after the first 120 books were drawn and downloaded and **after counting candidate sentences (945 in the 96 books within the length limits, a count that uses only the fixed cue list and no model output), but before any model has read any candidate and before any event exists.** It adds one rule to `PREREG_PD_CONFIRM_v2_L40S.md`; nothing else changes.

**Why.** At about 10 candidate sentences per book and a typical hit rate of a few percent, 120 books cannot be expected to give the 100 to 200 events the design needs. The original rules state that a shortfall is reported; this addendum instead fixes, in advance, how more books are drawn so that the number of events is not tuned to any result.

**Rule.** Round 1 is the existing draw (`PD_confirm_books_v1.json`, seed 20261101, 40 books per fame band). If fewer than 150 events are available after round 1's verification and audit, round 2 is drawn the same way (seed 20261102, 40 books per band from the eligible books not yet drawn; a band with fewer remaining books gives all of them), then round 3 (seed 20261103). The mining order is round, then the draw order inside the round. The event selection rule (at most 5 per book, books in mining order, stop at 150 events) is unchanged. A round is drawn and downloaded only from catalogue metadata and fame counts, never from anything mined. The dev/test split of a book depends only on its id (SHA-256 rule) and so is the same whatever the round. At most 3 rounds (360 books); if 150 events are still not reached, the shortfall is reported and nothing is padded.

**Order of operations (for the record).** Rounds 2 and 3 are drawn and downloaded now (cheap, metadata only), and all rounds are mined in one pass so that pod time is not wasted; selection still uses only the earlier rounds when they suffice, as stated above.
