# Addendum 1 to PREREG_T4_renaming_validity_v5.md (disclosed implementation correction)

Frozen `PREREG_T4_renaming_validity_v5.md` and `MANIFEST_T4_v5.json` (prereg hash) are unchanged. The v5 gate passed (G1 to G5 = 0) and the v5 resolver conditions ran once (`data/eval/chimera/t4_v5_results.json`): O2 and I at exactly 100% of 11,174 mentions, R at 11,170 of 11,174 (99.96%, Wilson lower bound 0.9991, the four changed mentions classified `evidence_loss`).

**Defect found in the negative control, not in the renamer or the engine.** The v5 prereg (section 3, via v4 section 3) described N' as breaking "containment and family structure on purpose", and the original T4 definition (v1 section 4, run N) is a renaming that handles "Yuan" **differently depending on context** (after "Fang " versus standalone), i.e. non-compositional. The v5 runner implemented N' as a second **consistent** cipher for tokens containing "yuan". A consistent token mapping is a function of the token alone and cannot break containment, so N' was insensitive by construction: it scored the same 11,170 of 11,174 as R. This was an implementation bug against the pre-registered intent, found by reading why N' did not drop (gate-versus-engine check), not by looking for a result.

**Correction (disclosed deviation).** Run N is re-implemented as the original definition in `scripts/chimera/t4_v5_negative_control.py` and run once alongside a fresh O1. Both versions are reported: N' (insensitive, as run) and N (context-dependent). The T4 verdict uses N under the v2 decision rule (PASS needs R at least 0.98 with Wilson lower bound at least 0.97, O1 = O2 = I at 100%, and N below R). No renamer, gate, vocabulary or threshold is changed.
